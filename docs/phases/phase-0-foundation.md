# Phase 0 Report: Research Charter, Governance, Recovery, and Project Foundation

## Phase

Phase 0 -- Research Charter, Governance, Recovery, and Project Foundation.

## Objective

Establish a recoverable research project foundation for Juniper Auto before
any expensive model, tokenizer, dataset, runtime, or training work begins:
research charter, governance, frozen architecture/dense-control
configuration with independently-derived parameter accounting, environment
specification and dependency locking, deterministic seeding, structured
logging, an experiment registry, time accounting, an ADR system, a phase
report system, artifact manifests and hashes, automated tests, CI, a single
validation entrypoint, recovery documentation, and a genuinely executed
clean-clone recovery exercise.

## Recovery status

**PASSED, twice.** Two isolated fresh-clone/fresh-venv recovery exercises
were executed during this engineering session (not merely described):

**Run 1** (before the self-review fix cycle, `git clone --no-local` from
the local repository into an isolated scratch directory sharing no state --
no `.venv`, no caches, no untracked files -- with the working checkout):
all 10 gates passed, 69/69 tests, foundation-probe checksum
`-42.402915954589844` under `seed=1234` on CPU.

**Run 2** (after the self-review fix cycle, and after the candidate commit
`88b4ed452dd477849b4041137130f52cc814fb5b` was actually pushed): `git clone
https://github.com/Cinqic/Juniper-Auto.git` -- a genuine clone from the
real GitHub remote, not a local path -- into a fresh scratch directory,
then:

1. `python3 -m venv .venv` + `python -m ensurepip --upgrade` + `pip install
   --upgrade pip`.
2. `pip install -r requirements-lock.txt` (hash-verified install of all 44
   pinned dependencies, including `torch`).
3. `pip install -e . --no-deps`.
4. `python scripts/validate_repo.py --all`.

Result: all 10 validation gates passed, 80/80 tests, foundation-probe
checksum `-42.402915954589844` under `seed=1234` on CPU -- identical to
Run 1 and to the primary FLOWBOX checkout, additional cross-process
determinism evidence.

Both runs are accurately isolated fresh-clone/fresh-environment exercises
on the same physical machine (FLOWBOX), not a literal from-scratch OS
reinstallation -- see "Accepted limitations" below. GitHub Actions CI
(`.github/workflows/phase-0-validation.yml`) separately validated on a
genuinely different, GitHub-hosted, CPU-only Linux machine; see "CI
workflow / run" above for that result.

## Accepted limitations

- No separate "complete Juniper Auto End-to-End Development Instructions"
  document was available to this session beyond the Phase 0 task
  instructions themselves, though those instructions refer to such a
  document as supplied and authoritative. The charter and governance
  documents are built from what was actually provided; see
  [docs/phases/phase-0-sonnet-self-review.md](phase-0-sonnet-self-review.md),
  Pass J, for detail. A future reviewer with access to the fuller document
  should diff it against `docs/research/project-charter.md`.
- License selection beyond the pre-existing MIT `LICENSE` is an open
  governance item, not decided by Sonnet (see
  [project-charter](../research/project-charter.md), License status).
- CUDA/GPU bitwise determinism is not claimed or tested -- only best-effort
  CPU determinism (`juniper_auto/util/seed.py`).
- The clean-clone recovery exercise is an isolated fresh-clone/fresh-venv
  test plus clean remote Linux CI, not a literal from-scratch OS
  reinstallation of the physical development machine.
- `nvcc`/system CUDA toolkit is not installed on FLOWBOX; PyTorch's bundled
  CUDA runtime libraries are relied on instead (see environment
  specification).
- No tokenizer, dataset, checkpoint, or runtime exists yet -- by design,
  this is Phase 1+ scope.
